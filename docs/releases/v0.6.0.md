# Protocol Sentinel v0.6.0

Released: **2026-11-04**. [Release tag](https://github.com/NothernZhongKui/protocol-sentinel/releases/tag/v0.6.0) · [Changelog](../../CHANGELOG.md) · [Workspace quickstart](../portable-workspace-v0.6.md)

## Included

- Separate workspace Direct EOA/UUPS runner for existing Git-pinned Foundry projects, including nested workspaces.
- Comparison Evidence 1.1, Git-owned compiler source closure and build-provenance v2.
- Original compiler-input replay with normalized independent solc outputs and Python classification replay.
- Trusted v2 policy bound to tool/consumer commits and GitHub workflow context.
- Independent completed-run verification, retaining `PASS`, `BLOCK` and `REVIEW` distinctions.

## Validation

The pinned Capminal external acceptance exercises safe and synthetic faulty **test-only** migrations, compiler replay, evidence verification and artifact mutation controls. A later real GitHub Actions external integration also observed the intended `CHANGED_TO_VIOLATION` / `REPLAY: MATCH` / `CI DECISION: BLOCK` outcome while ordinary Foundry tests passed. This is **not** a vulnerability claim about upstream Capminal. See the [historical RC review](v0.6.0-rc-review.md) for its pre-release evidence and limitations.

## Compatibility and limits

The existing v0.5 runner and Evidence 1.0 remain separate and supported as described in their own documentation. The v0.6 portable runner covers **one declared Direct EOA/UUPS attempt per invocation** with empty initialization calldata. It does not discover privileges, validate upgrade storage layout, independently authenticate original EVM execution, prove safety beyond the declared scenario or enforce GitHub merge rules on its own.

No published v0.6.0 code or evidence format changes are implied by subsequent documentation-only corrections to `main`.
