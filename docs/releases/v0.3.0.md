# Protocol Sentinel v0.3.0 — Mainnet Fork Authority Regression

## Overview

Protocol Sentinel v0.3.0 expands verification and reproducibility
for execution-based authority regression testing.

This experimental release introduces property-based fuzzing,
historical Ethereum mainnet fork integration and evidence reporting.

The Solidity AuthorityProbe API remains unchanged from v0.2.1.

## Highlights

### Property-based testing

- Seven Evaluator fuzz tests.
- Two isolation fuzz tests.
- Diagnostic precedence and context validation.
- Rejection evidence and policy classification checks.
- Repeated isolated UUPS probes.
- State restoration and authorization preservation.

### Authority regression

The same outsider is tested across three implementations:

1. Historical implementation: PASS.
2. Deliberately over-permissive test implementation: FAIL.
3. Corrected owner-restricted test implementation: PASS.

The test verifies actual upgrade execution, implementation
replacement, snapshot restoration and retained owner authority.

The over-permissive implementation is test-only.
No vulnerability in the historical Adapter8004 deployment
is asserted.

## Reproduce

Standard project tests:

    forge test
    python3 scripts/test_fork_result_validator.py

Historical mainnet fork:

    ETH_RPC_URL=https://eth.drpc.org bash scripts/reproduce_adapter8004_fork.sh

Generated evidence:

    artifacts/fork/adapter8004-mainnet-24995819.json

An archive-capable Ethereum RPC is required.

## Compatibility

- AuthorityProbe Solidity API unchanged from v0.2.1.
- UpgradeCheck and UpgradeCheckResult retained.
- DetailedUpgradeCheckResult retained.
- Current evidence schema remains 0.4.
- No new production execution adapters.

## Limitations

- Direct EOA execution model.
- Canonical UUPS upgradeToAndCall with empty initialization data.
- Declared actors, targets and policies only.
- No automatic privilege discovery.
- Matching revert data does not prove authorization causality.
- JSON reports do not authenticate EVM execution.
- Fork tests do not establish general application upgrade safety.

## Status

Experimental pre-1.0 release.
Not a comprehensive smart-contract security audit.
