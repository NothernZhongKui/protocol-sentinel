# Protocol Sentinel v1.0.0

**Release preparation:** 2026-11-05. This document accompanies the v1.0.0 release pull request. The tag and GitHub Release are created **after** approval and merge; no release is published by this PR.

Protocol Sentinel brings execution-based authority regression testing to an existing Git-pinned Foundry project. Developers declare the direct upgrade restriction they care about, run an isolated Foundry producer, receive verified Comparison Evidence 1.1 and enable a trusted `PASS` / `BLOCK` / `REVIEW` gate in GitHub Actions.

## Developer workflow

1. **Discover:** [First verified result](../v1-onboarding.md), using one pre-existing Foundry UUPS workspace.
2. **Configure:** `sentinel init --route direct-uups` generates a producer and TOML; the fixture deliberately fails until its real actor, target, candidate, expected revert and authorized transition are provided.
3. **Diagnose:** `sentinel doctor` checks pinned Git sources and configuration offline without altering files or claiming compiler replay.
4. **Verify:** the workspace runner executes the producer, authenticates tracked source ownership, independently recompiles compiler inputs, replays classification and publishes completed Evidence 1.1.
5. **Enforce:** a protected-base workflow supplies a trusted policy v2 pinned to the actual tested commit and approved Sentinel tool SHA. CI reports separate `PASS`, `BLOCK` and `REVIEW` outcomes; protect both gate and workflow integrity using repository branch rules.

A Git-pinned consumer can reuse compatible `forge-std` and OpenZeppelin dependencies without downloading duplicate Sentinel-owned development fixtures for the Direct route.

## Compatibility

- Public Solidity comparison interfaces and the separate OpenZeppelin Timelock helper are retained.
- The v0.5 portable runner and Evidence 1.0 remain supported independently of the workspace runner and Evidence 1.1.
- Strict tracked-source ownership, exact compiler identity and normalized compiler replay remain mandatory.
- Trusted policy v2, CI decision semantics and exit codes are unchanged: `0` PASS, `2` BLOCK or verification error, `3` REVIEW. Local runs without trusted policy report `NOT_EVALUATED`.

## Security and support boundary

The portable route covers **one declared Direct EOA/UUPS `upgradeToAndCall(address,bytes)` attempt with empty initialization data per invocation**. Sentinel does not discover privileges, validate storage-layout compatibility, authenticate original EVM execution or replace a contract audit. Python `REPLAY: MATCH` establishes consistency with recorded observations, not execution authenticity or merge approval. Protect trusted workflows, policy, pinned verifier and required producers with enforceable repository rules; a green job name alone is insufficient. Consumer GitHub plan permissions may affect available branch protections.

v1.0.0 deliberately retains this narrow tested route. New privilege-action classes and unassisted community onboarding feedback are follow-on work and are not represented as features or acceptance results of this release.
